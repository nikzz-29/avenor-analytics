# 1. PRODUCT VISION

## 1.1. Концепция

Avenor — современная платформа бизнес-аналитики, позволяющая пользователям импортировать данные, исследовать их, создавать интерактивные визуализации и собирать собственные аналитические рабочие пространства.

Продукт должен помогать отвечать на вопросы:

- Сколько компания заработала за определенный период?
- Как изменяются продажи?
- Какие товары приносят наибольшую выручку?
- Какие категории показывают рост или снижение?
- Кто самые ценные клиенты?
- Какие каналы продаж работают лучше остальных?
- Какие показатели изменились относительно прошлого периода?
- Какие тенденции можно обнаружить в данных?
- Какие отчеты необходимо регулярно просматривать?

Основная ценность Avenor — превращать исходные данные в понятную, удобную и красивую аналитическую картину.

## 1.2. Целевая аудитория

- Владельцы малого и среднего бизнеса.
- Аналитики.
- Предприниматели.
- Маркетологи.
- Руководители интернет-магазинов.
- Product Managers.
- Финансовые менеджеры.
- Небольшие команды, работающие с коммерческими данными.

## 1.3. Характер продукта

Avenor должен восприниматься как реальный современный B2B SaaS.

Не нужно искусственно усложнять продукт. Его интерфейс должен быть доступным даже человеку, который раньше не пользовался аналитическими системами.

Ориентируйся на принципы лучших инструментов вроде Linear, Vercel Dashboard, Stripe Dashboard и современных data-workspaces.

Не копируй их компоненты, внешний вид или фирменный стиль буквально.

Изучи их подходы к информационной архитектуре, плотности контента, типографике, состояниям интерфейса и организации сложных пользовательских сценариев.

Создай самостоятельный визуальный язык Avenor.

# 2. ПРИНЦИПЫ РАЗРАБОТКИ

Придерживайся следующих правил на протяжении всей работы.

8. Не используй устаревшие подходы, если есть стабильные современные решения.

14. Обеспечивай воспроизводимость сборки и тестов.
15. Фиксируй изменения в Git.

Предпочитай простые и понятные решения.

- Contemporary.

- Calm.
- Sophisticated.
- Functional.

# 7. MOTION & INTERACTIONS

Анимации — важная часть Avenor, но они должны быть функциональными и аккуратными.

Впечатление должно возникать от качества исполнения, а не от количества эффектов.

## 7.1. Основные принципы

Анимации должны:

- Быть плавными.
- Иметь естественную динамику.
- Подчеркивать изменение состояния.
- Помогать пользователю понимать интерфейс.
- Не мешать взаимодействию.
- Не ухудшать производительность.
- Поддерживать `prefers-reduced-motion`.

Предпочтительные диапазоны:

- Hover: 120–180 ms.
- Small interactions: 150–220 ms.
- Modal/dialog transitions: 180–260 ms.
- Panel transitions: 220–350 ms.
- Chart transitions: 250–450 ms.

Это ориентиры, а не жесткое правило.

Используй подходящие easing-функции или spring-физику.

## 7.2. Конкретные анимации

Реализуй:

**Navigation**

- Аккуратные переходы между разделами.
- Animated active state в Sidebar.
- Плавное раскрытие подменю.
- Корректную анимацию мобильной навигации.

**Cards**

- Минимальные hover-эффекты.
- Деликатное изменение фона и границы.
- Мягкое появление данных после загрузки.
- Отсутствие скачков layout.

**Charts**

- Плавное обновление значений.
- Animated transitions при переключении периода.
- Tooltip с аккуратным появлением.
- Выделение активных рядов.
- Плавную смену типа визуализации, когда это технически оправдано.

**Tables**

- Hover состояния строк.
- Понятные selected states.
- Анимации выпадающих меню.
- Ненавязчивые переходы при фильтрации и сортировке.

**Dialogs**

- Backdrop transitions.
- Subtle scale + opacity.
- Правильный focus management.
- Закрытие через Escape.

**Dashboard Builder**

- Плавное перетаскивание виджетов.
- Визуальное обозначение будущего положения блока.
- Анимацию перестроения сетки.
- Мягкое изменение размеров компонентов.

**Notifications**

- Умеренные toast-анимации.
- Автоматическое закрытие с достаточным временем на чтение.
- Понятные состояния success, warning, error.

Не анимируй всё одновременно.

Не делай тяжелые full-page transitions, которые замедляют работу.

# 8. RESPONSIVE DESIGN

Приложение должно полноценно работать на desktop, tablet и mobile.

## Data Integrity

Для денежных значений используй Decimal / PostgreSQL NUMERIC, а не float.

Учитывай валюту и точность.

Не смешивай значения разных валют без явного пересчета.

Определи правила учета:

- Оплаченных заказов.
- Отмен.
- Возвратов.
- Частичных возвратов.
- Скидок.
- Повторных заказов.

- Часовые пояса.

Опиши формулы метрик в документации.

**Действуй: исследуй → проектируй → реализуй → запускай → тестируй → исправляй → коммить.**

Постоянно используй доступные инструменты проверки.

Если технология, подход или API тебе незнакомы либо могли измениться, сначала изучи актуальную официальную документацию.

Не выдумывай API библиотек.

Не используй устаревшие примеры без проверки.

Не создавай заглушки вместо обязательного функционала.

Не останавливайся после создания красивого интерфейса.

Не считай задачу выполненной без проверки backend и интеграции с frontend.

Не задавай лишних вопросов, если можешь принять обоснованное решение самостоятельно.

При обнаружении проблемы сначала постарайся диагностировать и решить ее.

Поддерживай понятные локальные Git-коммиты.

**Ничего не отправляй на GitHub автоматически.**

Особое внимание уделяй:

- UI/UX.
- Motion Design.
- Адаптивности.
- Реальной аналитической логике.
- Безопасности.
- Архитектуре.
- Тестированию.
- Чистоте кода.
- Производительности.
- Целостности данных.

Начни с проверки проекта и доступных инструментов, составь краткий план, после чего переходи к реальной реализации.

Главная цель — создать Avenor Analytics: красивый, быстрый, надежный, продуманный аналитический инструмент, который можно уверенно демонстрировать потенциальным клиентам и использовать как серьезный Fullstack-проект в портфолио.
